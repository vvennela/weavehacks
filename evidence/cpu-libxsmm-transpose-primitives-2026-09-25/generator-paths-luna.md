# LIBXSMM SME full-shape transpose descriptor paths

Source inspected read-only: pinned LIBXSMM commit `10490f10e79d4511f252c33279ef970a188cfab6`, `src/generator_gemm.c` and `src/generator_gemm_sme.c`. The M4 dispatcher accepts FP32 XGEMM ABI descriptors with `BETA_0` plus none, either, or both of `TRANS_A` and `TRANS_B`; it strips beta-zero only for the supported-flag check and passes the descriptor to the SME blocking generator (`generator_gemm.c`, lines 1283–1295). These are legal generator descriptors, but they do not by themselves preserve the current row-major `C=A*B` mapping.

For the full 512×512×512 path, blocking gives 64-column N tiles and 32-row M tiles. In the main full-block branch, the generator handles B outside the M loop and A inside it (`generator_gemm_sme.c`, lines 651–683). This makes the effects of the flags distinct:

| Descriptor | Generator behavior relative to NN | Layout and implementation constraint |
| --- | --- | --- |
| `TRANS_A` only | **Adds A packing** through `transpose_a_to_stack` in each 32-row M block, while **retaining B packing** through `transpose_b_to_stack` for each 64-column N tile. The A transpose helper allocates a packed-A region and transposes K chunks (`generator_gemm_sme.c`, lines 285–403); its call is at lines 679–683. | No packing is removed. The flag changes `op(A)`, so the A pointer and storage must represent the matrix required by that transposed operation. Current row-major pointers cannot simply be reused. |
| `TRANS_B` only | **Skips B packing to stack**. The N-tile setup takes the direct-B path instead of calling `transpose_b_to_stack` (`generator_gemm_sme.c`, lines 660–671); later pointer updates also branch on the flag (lines 761–770). It does not add A-transpose packing. | This is the only single-flag path that removes one NN packing operation. The B operand must be stored in the physical layout expected by `op(B)`; setting the flag on the present row-major `A` argument changes the mathematical operation and is incorrect without a matching remap/transform. |
| `TRANS_A|TRANS_B` | **Skips B packing and adds A packing**. The transpose-A helper sizes its packed-A allocation with no B-stack component when `TRANS_B` is set (`generator_gemm_sme.c`, lines 343–347), and the full-block M loop still calls that helper (lines 679–683). | It exchanges which operand is packed; it is not a no-pack path. Both logical operations change, so both physical input layouts and pointer mapping need to be matched. Current pointers are not a valid drop-in. |

In NN, B is packed before each 64-column N tile and then reused by its M tiles; A is read in the generator’s expected layout. Therefore source facts show that `TRANS_B` removes that generator B-stack packing path, while `TRANS_A` adds A-stack packing. The source does not establish whether any variant is faster after the required layout conversions. The timed call must include any input transformation, allocation, and cleanup. All three variants need an exported full-shape primitive, an explicit row-major mapping, guarded correctness against fresh inputs, and byte/relocation/license review before Sera can use them.
