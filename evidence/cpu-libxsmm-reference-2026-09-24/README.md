# Standalone LIBXSMM SME reference

The user selected the published LIBXSMM SME approach as the new starting point. This is an imported reference baseline, not a Sera-discovered speedup.

## What was reproduced

The authors' [results](https://github.com/scalable-analyses/sme/tree/c9de42a561c9c3bf9e926748fb5113a075d1f096) report 1755.189780 GFLOP/s for the ordinary case and 1833.867522 for the transposed accumulation case. Their instructions do not pin LIBXSMM. This reproduction pins upstream LIBXSMM to `10490f10e79d4511f252c33279ef970a188cfab6`; it does not claim to reproduce the historical dependency revision or timing conditions.

`export_kernel.c` dispatches the current generator for FP32 512x512x512, alpha=1, beta=0, no transpose, and no prefetch. It exports the 2,500 generated bytes offline. The runtime uses no LIBXSMM library. Generated packing and stack allocation execute inside each kernel call; no matrix values or answers are cached. The public row-major ABI swaps A and B for the equivalent column-major product C^T=B^T*A^T. Other dimensions use the previous general SME fallback.

`source/kernel.c` preserves the raw generated instructions. `make_editable.py` translates the disassembly to editable assembly in `editable/kernel.c`. A byte-for-byte reassembly check passed for all 2,500 bytes. The BSD-3-Clause notice is retained in both sources and `LICENSE.libxsmm.md`. Compiler flags and the frozen hill are unchanged.

## Local result

The editable reference passes 48 deterministic public correctness cases. Its three validation reports measured **1541.253, 1333.284, and 1328.067 GFLOP/s**; the final held-out report measured **1533.190 GFLOP/s**. The 1,800 target is unmet. This baseline-only run made zero model calls; subsequent optimization uses Sera's 15-Luna specialist swarm and Astra-high implementation/review.

AC and unchanged power settings were checked before and after every report. User idle confirmation is recorded; it does not prove the OS had no competing work. The upstream repeated-call harness and our fresh-input/allocation-inclusive hill are different timing contracts. See the Luna [benchmark audit](benchmark-contract-luna.md) and [algorithm note](algorithm-luna.md).

## Reproduction

Build the pinned upstream clone with `make -j2 BLAS=0 STATIC=1`. Compile `export_kernel.c` against its include directory and static library, then export `kernel-512.bin`. Compile the self-contained C with the frozen flags and disassemble it with Apple LLVM's SME2 decoder. Run `make_editable.py`, compile its output, and compare the first 2,500 instruction bytes with the exported binary. `assembly-roundtrip.json` records that check. `source-provenance.json`, `export.json`, the generated sources, and full disassembly preserve the derivation.

The scored command was:

```sh
PYTHONPATH=. /tmp/sera-audit-venv/bin/python examples/optimize_cpu_kernel.py --baseline evidence/cpu-libxsmm-reference-2026-09-24/editable/kernel.c --hill-workspace /Users/vishnuv/Documents/Documents/kernel-opt --output evidence/cpu-libxsmm-reference-2026-09-24/baseline-run --max-candidates 0 --max-model-calls 1 --max-seconds 300
```

This is a machine-specific research artifact, not a portable deployment package. It assumes the verified M4 Pro SME2 hardware and the pinned ABI.
