## What the generator does

At this revision, the 32x32 path loads two paired FP32 vectors for A and two for B with SME2 `LD1W_2`, then issues four `FMOPA` operations into four ZA.S tiles for each K step. This is one 32x32 output microtile, using four FP32 ZA tiles, with the two operands reused across the four outer products. Other generator paths cover 64x16 and 16x64 tile shapes. The higher-level generator handles blocking, K iteration, masks, C accumulation/store, and input transpose paths; A transpose helpers include on-the-fly transpose/stack code. These details describe the pinned upstream source, not necessarily the exact unpinned revision behind the README numbers.

The benchmark command's documented fields set FP32 inputs/compute/output, dimensions and leading dimensions to 512, alpha=1, beta=1, aligned A/C, no prefetch, no batch reduction, batch count 1, batch-unroll 0, 10,000 repetitions, and internal tile configuration. The two commands differ in `trans_b`: 0 and 1. The second score is therefore specifically for accumulation with transposed B. The harness performs a correctness call and dispatches JIT before starting the timed repetitions. Generated transpose/packing work inside each kernel invocation remains in the timed kernel. This does not match a beta=0 frozen-hill contract.

## Standalone adaptation path (design proposal, not tested)

Implement a small fixed-shape C wrapper with a function-level SME2 target and inline assembly for a 32x32 FP32 microtile. Use four ZA.S accumulators; for each K step issue paired loads from contiguous packed panels, then the four FMOPA updates. Keep ZA live for the full K loop. Store the completed ZA tile to row-major C with explicit row addressing and the hill's beta=0 semantics; add a separate masked/tail path for general sizes. Use clean re-expression of the algorithm in our kernel rather than adding LIBXSMM as a runtime dependency.

For row-major `C = A*B`, the direct column-major identity is `C^T = B^T*A^T`: view row-major B as column-major B^T, row-major A as column-major A^T, swap operand order, and view row-major C as column-major C^T. This yields column-major dimensions `(n,m,k)` and contiguous leading dimensions for dense square matrices. Keep explicit leading dimensions and tests for non-square shapes and tails; square n=512 alone cannot detect all orientation errors.

Inline assembly must preserve the platform ABI, enter/exit streaming mode correctly, and pass all signed-hill correctness and timing checks. The pinned LIBXSMM source can inform instruction scheduling and transpose handling, but its implementation is not a drop-in: it has library-generated prologue/epilogue and macro-kernel behavior. The published rates are reference context only; they promise no gain for this standalone kernel.
