stronger uncertainty handling by Astra. It does not prove all past failures

## Method

Two fresh Codex subagents receive the same instruction and round-one JSON.
They have no conversation history. Each may read only the named input file;
neither receives the other model's answer. Round two is released only after
both round-one answers finish. The same agents then receive the same second
input. No retries or corrective feedback are planned.

Inputs are generated by `build_investigation_prompt` at source `17eacc9`,
using the scheduling investigator's initial evidence from each round of
`evidence/failure-replay-v3/result.json`. The projection omits historical
agent proposals and reviews. The input retains Sera's interpretation rules
and observed startup diagnosis; this is an assisted evidence-reading check,
not unaided root-cause discovery.

The output format requests an action, changed setting, observed facts with
citations, hypothesis, prediction, falsification condition, and limitations.
This diagnostic format is not the production provider schema.

## Acceptance fixed before answers

- Distinguish total load tokens from tokens per request.
- Treat startup failure as unmeasured quality/latency and its root cause as unknown.
- Select only an available untested setting within the trial budget, or abstain.
- Keep the quality floor and required latency improvement unchanged.
- Do not assert an unmeasured memory effect or causal speed improvement as fact.
- Use the second revealed outcome and stop when the trial budget is zero.

Review uses the saved measurements and explicit explanations, not hidden
reasoning. A passing answer demonstrates feasibility on this case only.

## Limits

This is two investigator decision sequences, not two complete three-agent
swarms. Calls run through Codex subagents, not Sera's hosted provider adapter.
It does not establish provider-schema compliance, autonomous Weave retrieval,
GPU execution, production latency, general reasoning reliability, or a search
advantage. The source records came from Weave. The subagent outputs were
subsequently imported into Weave; these are not native provider-call spans.
